## 1. The DRBD Out-of-Tree Build System

DRBD in this repo is an **out-of-tree kernel module** — it builds against installed kernel headers rather than being compiled inside the kernel source tree.

```bash
ls -la drbd/Makefile Makefile Kbuild 2>/dev/null || find . -name Makefile | head -10
cat Makefile
```

### Top-Level Makefile Structure

```bash
grep -n "KDIR\|KVER\|modules\|install\|MODPROBE\|COMPAT\|coccinelle" Makefile | head -30
```

Key variables:
```makefile
KVER  ?= $(shell uname -r)
KDIR  ?= /lib/modules/$(KVER)/build
# KDIR points to: /lib/modules/5.15.0-generic/build
# which symlinks to: /usr/src/linux-headers-5.15.0-generic

# Build all modules:
all:
    $(MAKE) -C $(KDIR) M=$(PWD)/drbd modules

# Install:
install:
    $(MAKE) -C $(KDIR) M=$(PWD)/drbd modules_install
    depmod -a $(KVER)

# Build compatibility layer:
compat:
    $(MAKE) -C $(KDIR) M=$(PWD)/drbd/compat
```

## 4. The Compat Layer — `drbd/compat/`

Because DRBD runs on many kernel versions (4.x through 6.x+), it uses a compatibility layer to abstract kernel API differences:

```bash
ls drbd/compat/
cat drbd/compat/compat.h 2>/dev/null || find drbd/compat -name '*.h' | head -5
```

```bash
grep -rn "COMPAT_HAVE\|drbd_compat\|#ifndef COMPAT_HAVE\|#ifdef COMPAT" drbd/compat/ | head -20
```

Examples of compat shims:

```c
// drbd/compat/compat.h

// blk_queue_make_request() was removed in kernel 5.9
#ifdef COMPAT_HAVE_BLK_ALLOC_DISK
#define drbd_alloc_disk(node) blk_alloc_disk(node)
#else
#define drbd_alloc_disk(node) alloc_disk(1)
#endif

// bio_set_dev() added in 4.14
#ifndef COMPAT_HAVE_BIO_SET_DEV
static inline void bio_set_dev(struct bio *bio, struct block_device *bdev)
{
    bio->bi_bdev = bdev;
}
#endif

// submit_bio_noacct() added in 5.11
#ifdef COMPAT_HAVE_SUBMIT_BIO_NOACCT
#define drbd_submit_bio(bio) submit_bio_noacct(bio)
#else
#define drbd_submit_bio(bio) generic_make_request(bio)
#endif
```

## 5. Compat Detection at Build Time

```bash
ls drbd/compat/tests/ 2>/dev/null || find drbd/compat -name '*.c' | head -10
```

Each compat feature is tested by trying to compile a small C snippet:

```makefile
# drbd/compat/Makefile:
$(shell if grep -q "blk_alloc_disk" $(KDIR)/include/linux/blkdev.h; then \
    echo "#define COMPAT_HAVE_BLK_ALLOC_DISK 1"; \
fi >> drbd/compat/compat.h)
```

Or using the `autoconf`-style test files:

```bash
# test file: drbd/compat/tests/have_blk_alloc_disk.c
#include <linux/blkdev.h>
void test(void) { blk_alloc_disk(0); }
```

If the test compiles: `COMPAT_HAVE_BLK_ALLOC_DISK` is defined. If not: the compat shim is used.

## 6. Coccinelle Semantic Patches

Coccinelle (`spatch`) is a source-to-source transformation tool for C. DRBD uses it for:
- Mechanical refactoring across many files
- Finding/fixing patterns that simple grep would miss
- Adapting to kernel API changes

```bash
find . -name '*.cocci' | head -10
ls coccinelle/ 2>/dev/null
```

### Example: Converting `bdevname()` to `bdev_name()`

A Coccinelle semantic patch (`.cocci` file):

```coccinelle
@@
expression bdev, buf;
@@
- bdevname(bdev, buf)
+ bdev_name(bdev)
```

Apply it:
```bash
spatch --sp-file convert_bdevname.cocci --in-place drbd/*.c
```

### Example: Fixing a Missing `put_ldev()` on Error Path

```coccinelle
@@
struct drbd_device *device;
expression E;
@@
  if (!get_ldev(device))
    return E;
  ...
+ put_ldev(device);
  return E;
```

This finds all `get_ldev()` calls that return without `put_ldev()` — a resource leak pattern.

## 7. Reading a DRBD Kernel Patch

Let's study the structure of a real DRBD patch:

```bash
git log --oneline drbd/ | head -20
git show HEAD -- drbd/drbd_main.c | head -60
```

A well-structured DRBD patch has this format:

```
drbd: fix missing put_ldev() in error path of drbd_adm_attach()

When drbd_adm_attach() fails after calling get_ldev_if_state() at
step 12, it returns without calling put_ldev(), leaving local_cnt
incremented permanently. This prevents any future disk detach.

Fix: add put_ldev() on all error paths after step 12.

Reported-by: User Name <user@example.com>
Fixes: abc12345 ("drbd: introduce get_ldev_if_state reference counting")
Signed-off-by: Developer <dev@linbit.com>
---
 drbd/drbd_nl.c | 6 ++++++
 1 file changed, 6 insertions(+)

diff --git a/drbd/drbd_nl.c b/drbd/drbd_nl.c
index abc1234..def5678 100644
--- a/drbd/drbd_nl.c
+++ b/drbd/drbd_nl.c
@@ -1234,6 +1234,12 @@ int drbd_adm_attach(...)
     ...
+    if (err)
+        put_ldev(device);
     goto out;
```

Key sections of a kernel patch:
1. **Subject line:** `drbd: <subsystem>: one-line description`
2. **Body:** What problem, why it happens, what the fix does
3. **Tags:** `Fixes:`, `Reported-by:`, `Signed-off-by:`
4. **Diff:** Minimal, focused change

## 8. Writing a DRBD Patch — Workflow

### Step 1: Identify the bug / improvement

```bash
# Example: find all places where rq_lock is taken but never released
grep -n "spin_lock.*req_lock" drbd/drbd_req.c | head -20
# Cross-reference with spin_unlock_irq
grep -n "spin_unlock.*req_lock" drbd/drbd_req.c | wc -l
```

### Step 2: Make the change

```bash
cd drbd/
# Edit the relevant file(s)
vim drbd_req.c
```

### Step 3: Build and test

```bash
make -C /lib/modules/$(uname -r)/build M=$(pwd)/drbd clean
make -C /lib/modules/$(uname -r)/build M=$(pwd)/drbd modules 2>&1 | grep -E "error:|warning:"

# On a test VM:
sudo rmmod drbd_transport_tcp drbd
sudo insmod drbd/drbd.ko
sudo insmod drbd/drbd_transport_tcp.ko
dmesg | tail -5
```

### Step 4: Format the patch

```bash
git add -p drbd/drbd_req.c   # stage interactively
git commit -s                 # -s adds Signed-off-by
git format-patch HEAD~1      # generates 0001-drbd-fix-....patch
```

### Step 5: Check with scripts

```bash
# Linux kernel style checker:
./scripts/checkpatch.pl 0001-drbd-fix-....patch

# Coccinelle check for common patterns:
spatch --sp-file scripts/coccinelle/locks/double_lock.cocci drbd/*.c
```

## 9. Common DRBD Patch Patterns

### Pattern 1: Error path cleanup
```bash
# Check: every get_ldev() has a matching put_ldev()
grep -n "get_ldev\b\|put_ldev\b" drbd/drbd_nl.c | grep -v "^.*//.*get_ldev"
```

### Pattern 2: Lock ordering
```bash
# DRBD lock order: adm_mutex > req_lock > al_lock > bm_lock
# Find potential inversions:
grep -n "spin_lock.*req_lock\|mutex_lock.*adm_mutex" drbd/*.c | sort
```

### Pattern 3: RCU correctness
```bash
# rcu_dereference() must be inside rcu_read_lock()
grep -n "rcu_dereference\b" drbd/*.c | while read line; do
    file=$(echo $line | cut -d: -f1)
    lineno=$(echo $line | cut -d: -f2)
    # Check if rcu_read_lock() appears nearby
    awk "NR>$((lineno-10)) && NR<$lineno" $file | grep -q "rcu_read_lock" || \
        echo "POSSIBLE BUG: $line"
done
```

### Pattern 4: Missing `wake_up()` after state change
```bash
# After clearing a wait condition, wake_up() must be called
grep -n "state_wait\|misc_wait\|al_wait" drbd/*.c | grep -v "wake_up\|wait_event" | head -20
```

## Summary

DRBD builds as an out-of-tree kernel module using a standard `$(MAKE) -C $(KDIR) M=...` invocation. The compat layer (`drbd/compat/`) uses compile-time feature detection to abstract kernel API differences across versions. `drbd_buildtag.c` is auto-generated from git metadata. Coccinelle semantic patches enable safe mechanical refactoring. A proper DRBD kernel patch follows Linux kernel conventions: focused diff, descriptive commit message, `Fixes:` tag for regressions, `Signed-off-by:` chain, and passing `checkpatch.pl`.
